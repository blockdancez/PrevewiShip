# SEO 月末发布闭环与九月复盘设计

日期：2026-08-31

## 背景与批准范围

2026-08-31 的月末复盘显示，8 月 1–28 日 Google 自然搜索点击较 7 月同期增长 64.9%，最近完整七天的核心非 Netlify 页面点击增长 21.2%，Google AI 展现增长 22.1%。与此同时，发布台账仍未记录实际发布日期和公开 URL，GitHub/npm 的素材级归因尚未公开，首页品牌点击与 Free Hosting 页排名需要小范围优化。

用户已明确批准“归因、SEO、发布与复盘全量闭环”，包括 GitHub 推送、`previewship-mcp` npm 发布、可验证台账更新、首页与 Free Hosting 页优化，以及 9 月 7/14/28 日只读复盘任务。

## 方案选择

### 方案 A：全量闭环（采用）

在不扩建新关键词页面的前提下，完成归因发布、两处证据驱动的 SEO 优化、发布凭证治理和定期复盘。它能同时解决“流量增长但渠道不可归因”和“页面有信号但缺少针对性维护”两个问题。

### 方案 B：只修归因和发布

风险更低，但会错过首页品牌点击下降和 Free Hosting 排名下降的明确优化窗口，不采用。

### 方案 C：只优化 SEO 页面

无法修复发布台账、GitHub/npm 素材级归因与后续复盘数据链路，不采用。

## 一、发布台账语义

- 用户确认 72 条计划均已于 2026-08-31 发布，因此全部记录实际日期并从 `paused` 转为 `published_pending_verification`。
- 只有能够从公开页面、官方包注册表或已发布仓库精确核验的记录才转为 `published` 并填写 `public_url`。
- 不猜测帖子 ID，不把平台首页当作单条内容的公开 URL，不用搜索结果页代替发布凭证。
- 7/14/28 天复盘字段继续保持 `pending`，由后续只读复盘任务更新结论。

## 二、GitHub 与 npm 归因发布

- 保留现有 README 深链，只补齐素材级 `utm_content`，不改变 canonical 内容落点。
- 将 `previewship-mcp` 从 `1.0.13` 升级至 `1.0.14`，同步 package-lock。
- 发布前依次执行类型检查、构建、`npm pack --dry-run` 与包内 README/版本核验。
- 根仓库提交并推送后，再发布 npm；发布完成后从 GitHub raw 与 npm registry 反向核验。
- npm 认证、2FA 或权限失败时不绕过，保留已验证 Git 成果和可重试的本地版本。

## 三、SEO 优化边界

- 只修改首页和英文 `/guides/free-static-website-hosting`，不新增 URL，不修改 canonical、hreflang 或索引策略。
- 首页强化“上传浏览器就绪静态产物并获得预览 URL”的非品牌价值表达，同时保留品牌和产品定位；不改核心 CTA 路径和事件名称。
- Free Hosting 页保持“预览而非生产托管”的可信边界，在标题、摘要、首屏答案和内链中更清晰覆盖 `free static website hosting`、`host HTML file online free` 和浏览器就绪 ZIP 意图。
- 不修改正在增长的 Upload、Host、Claude、繁中和西语页面，避免干扰已形成的搜索信号。
- 更新 `updatedAt`，并复用现有内容模型、结构化数据和静态 SEO 校验。

## 四、验证、提交与发布

- 根仓库和 Console 是两个独立 Git 仓库，分别检查未提交改动、运行对应测试并提交，禁止强推。
- 根仓库只提交本设计、实施计划、README/MCP 版本和发布台账等本次相关文件。
- Console 只提交页面文案和相应测试/快照；如生产部署由推送自动触发，则在推送后用公开 HTML 核验标题、描述、canonical、robots 与结构化数据。
- 所有无法安全验证的外部平台记录保留“待核验”，不阻塞已验证渠道完成闭环。

## 五、九月复盘任务

- 2026-09-07：首轮发布归因复盘，重点检查渠道访问、注册意图、成功部署与新页面查询变化。
- 2026-09-14：中期复盘，判断 CTR、排名和转化是否达到可比较状态。
- 2026-09-28：28 天复盘，决定保留、改写、停止或扩大具体渠道。
- 三次任务均只读，不自动修改站点、发布内容或操作预算；后台未登录时明确报告缺失数据。

## 异常与回滚

- npm 发布不可覆盖旧版本；发布失败时停止在可重试状态，不修改 dist-tag 指向未知版本。
- SEO 改动不改变路由、canonical 和业务逻辑，必要时可按 Console 单独提交回滚。
- 台账保留发布事实与验证状态的区别；后续发现链接错误时修正 URL，不抹除原发布日期。
- 不删除用户现有文件、不重写历史、不强制覆盖远端分支。

## 验收标准

1. GitHub 公开 README 的目标深链包含唯一 `utm_content`。
2. npm registry 存在 `previewship-mcp@1.0.14`，包内 README 使用新 URL 和素材级归因。
3. 72 条台账均有实际日期和可解释状态；公开 URL 只出现在可核验记录中。
4. 首页和 Free Hosting 页通过 Console 类型检查、测试、构建及 SEO 校验。
5. 公开页面保留正确 canonical、index/follow、结构化数据和主要 CTA。
6. 9 月 7/14/28 日只读复盘任务创建成功。
