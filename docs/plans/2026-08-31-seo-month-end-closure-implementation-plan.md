# SEO 月末发布闭环实施计划

日期：2026-08-31

关联设计：`2026-08-31-seo-month-end-closure-design.md`

## 实施切片

1. **归因与包发布准备**：校验现有 README UTM 差异，将 MCP 版本升至 `1.0.14`，执行类型检查、构建和包内容预检。
2. **发布台账**：将 72 条用户确认发布的记录写入实际日期和待核验状态；完成 GitHub/npm/公开可见视频等精确 URL 的反向核验后，仅更新对应行。
3. **根仓库发布**：提交 README、MCP 版本与台账，拉取远端状态，非强制推送 `main`，核验 GitHub raw 内容。
4. **npm 发布**：确认注册表无 `1.0.14`，发布包并反向读取版本、README 和关键归因参数；认证失败时停止并保留可重试状态。
5. **SEO 小范围优化**：在 Console 中仅修改首页公共文案源与英文 Free Hosting 内容，更新必要测试，不改变路由、canonical、索引策略或事件名称。
6. **Console 验收与发布**：执行类型检查、单元测试、公共 SEO 校验和生产构建；提交并非强制推送 `main`，随后核验生产 HTML。
7. **定期复盘**：创建 9 月 7/14/28 日三次只读任务，复用 GSC、AI 搜索、Bing和站内分析口径；缺失登录时只报告阻塞。
8. **最终审计**：核对两个仓库状态、远端提交、npm 版本、台账统计、生产标题/描述/canonical/robots/schema 和复盘任务状态。

## 测试与安全纪律

- 先读取现有测试与内容生成逻辑，再做最小改动；不复制页面或创建新的关键词变体。
- 使用现有脚本和包管理器；文件修改通过补丁完成，生成物由既有构建脚本产生。
- 每个仓库只提交本次相关文件；保留用户无关改动，不使用强推或破坏性 Git 命令。
- 不猜测外部内容 URL，不把账号主页、搜索页或重定向中间页写入单条发布记录。
- npm、GitHub或部署失败时记录精确失败点，已验证的前置成果保持可回滚、可重试。
