# 增长可信度、索引质量与分发资产治理实施计划

日期：2026-08-24

关联设计：`2026-08-24-growth-trust-and-distribution-design.md`

## 纵向切片

1. 业务事实边界：先补客户端伪造与 Worker 事件失败测试，再限制事件门禁、校验上下文并把 Ready 旅程改为 Deployment 权威事实。
2. 旅程口径：以一个 canonical journey 查询统一 Summary/Funnel/Source/Details，加入时序与合计不变量测试，随后优化重复查询和缓存元数据。
3. Stripe 幂等：先覆盖乱序/重复/部分退款行为，再落地 inbox/pending、补偿任务和唯一索引。
4. 前端安全与 Showcase：先补 JSON-LD 注入、构建空集合、索引过滤和图片加载测试，再做最小实现与 SSG 质量门禁。
5. 索引生命周期：基于 2026-08-24 GSC/Bing 证据生成 overrides，补全 IndexNow 多 URL 入队与监控测试。
6. 运营素材：修订 UTM、落点、CTA、Alt、时长、事实表述与发布账本；使用图像编辑去除截图邮箱；更新 Remotion 页脚和验证后重渲染七条视频。
7. 系统验收：分别运行 Backend、Console、MCP、SEO、运营包、Remotion 测试/构建，并检查各仓库 diff、迁移兼容性与最终资产。

## 实施纪律

- 每个切片执行一个行为测试 → 最小实现 → 回归 → 重构，不横向批量先写所有测试。
- 代理只编辑独立文件域；共享文件由主线程审查或指定唯一所有者。
- 不在本轮部署生产或发布公开内容。
- 任何无法以现有数据安全判断的 URL 不做重定向，先保留并标记观察。
