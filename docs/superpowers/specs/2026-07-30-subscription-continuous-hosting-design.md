# 订阅有效期间持续托管设计

- 日期：2026-07-30
- 状态：已实施，待发布
- 范围：普通 CUSTOMER 账号的预览托管生命周期、订阅恢复、通知和前端表达

## 背景

当前 PreviewShip 在部署成功时按照套餐写入固定预览有效期：

- Free：3 天
- Pro Monthly：30 天
- Pro Yearly：365 天

清理任务在 `preview_expires_at` 到期后删除在线部署文件、清除项目 `current`，并发布过期页。结果是正常付费且持续续费的用户仍需要定期重新部署，付费权益和网站可用性没有保持一致。

本次调整将 Pro 的托管规则从“每次部署固定保留一段时间”改成“订阅有效期间持续托管”。月付和年付都获得持续托管，年付通过一次保障十二个月、价格优惠、更高额度和更长历史能力体现价值。

## 目标

1. Pro 订阅有效期间，项目固定链接不会因为部署时间到期。
2. 正常续费只延长托管租约，不创建新部署、不切换 URL、不消耗部署额度。
3. 订阅取消或扣费失败后，项目在当前付费周期结束后获得统一 3 天托管宽限期。
4. 已过期项目重新订阅时，如果 retained artifact 仍存在，系统自动恢复且不消耗部署额度。
5. 多项目重新订阅时，按照新套餐项目上限自动恢复最近使用的项目，超额项目归档但不删除数据。
6. 邮件、控制台和公开过期页准确表达当前状态，同时不向公开访问者泄露所有者的套餐或账单信息。
7. INTERNAL、免注册项目、Abuse 封禁和主动删除行为保持独立，不被商业订阅覆盖。

## 非目标

- 不改变 Stripe 商品、优惠券和支付价格。
- 不把 PreviewShip 变成无限期保存所有历史产物的归档系统。
- 不保证 retained artifact 已删除后仍可无文件恢复。
- 不改变项目固定链接的 slug。
- 不让付费权益绕过 Abuse 封禁、安全限制或主动删除。
- 不为普通续费创建新的部署记录。

## 领域概念

### 持续托管

只要 Pro 订阅保持有效，项目当前成功版本持续通过固定链接访问。正常续费只更新托管租约。

### 当前保障周期

用户已经完成付款的订阅周期。月付一次保障一个月，年付一次保障十二个月。

### 托管截止时间

系统允许项目继续在线的技术截止时间：

```text
Free = 部署成功时间 + 3 天
Pro = Stripe currentPeriodEnd + 3 天宽限期
```

它是托管生命周期字段，不再表示 Pro 用户必须在该日期前手动重新部署。

### 托管宽限期

当前付费周期结束后的 3 天。宽限期保留现有网站和访问方式，但不继续授予新的 Pro 商业额度。

### 自动恢复

项目已过期后，使用 latest retained artifact 创建一次新的异步部署。恢复成功后原固定链接重新开放，来源部署保持不可变。

### 套餐归档

重新订阅时，超过新套餐项目上限的历史项目不自动恢复、不公开托管，但项目和部署记录不删除。retained artifact 仍遵循对应套餐的正常保留规则，不承诺无限期保存。用户可以升级套餐或释放项目槽位后恢复。

## 产品规则

### 套餐托管规则

| 账号或套餐 | 托管规则 |
|---|---|
| 免注册 | 保持现有 24 小时临时预览 |
| Free | 每次成功部署保留 3 天 |
| Pro Monthly | 订阅有效期间持续托管；当前周期一次保障 1 个月 |
| Pro Yearly | 订阅有效期间持续托管；当前周期一次保障 12 个月 |
| INTERNAL | 不自动过期，保持现有内部账号策略 |

### 托管截止时间计算

1. Free 成功部署：`readyAt + 3 天`。
2. Pro 且 `currentPeriodEnd` 存在：`currentPeriodEnd + 3 天`。
3. Pro ACTIVE 但 `currentPeriodEnd` 暂时缺失：使用“当前时间 + 48 小时”的滚动安全租约；每次清理前重新确认，Stripe 每小时对账负责补齐周期。
4. INTERNAL：`null`。
5. Abuse BLOCKED：无论订阅状态如何都不能延长或恢复。

订阅权益和托管宽限是两个概念。进入 PAST_DUE 或 CANCELED 后，账号的新请求按 Free 权益处理，但已在线项目仍可运行至已写入的托管截止时间。

### 订阅状态转换

#### Free 项目未过期时订阅

1. Stripe Webhook 或对账确认订阅 ACTIVE。
2. 系统把符合新套餐项目额度的 READY latest 部署更新为 `currentPeriodEnd + 3 天`。
3. 不创建部署、不操作托管渠道、不改变固定链接。
4. 项目访问无中断。

#### 正常自动续费

1. Stripe 将 `currentPeriodEnd` 推进到下一周期。
2. 系统把项目托管截止时间更新为新的 `currentPeriodEnd + 3 天`。
3. 月付每次延长一个月，年付每次延长十二个月。
4. 清理任务在执行任何删除前再次确认账号权益；有效 Pro 必须续租并跳过删除。

#### 提前取消自动续订

1. `cancelAtPeriodEnd=true` 时订阅仍为 ACTIVE。
2. 项目继续运行至当前 `currentPeriodEnd + 3 天`。
3. 用户在周期结束前恢复自动续订，不会发生中断；下一次成功续费后正常延长。
4. 用户在周期结束后的 3 天宽限期内重新订阅，项目仍在线，直接更新租约。

#### 扣费失败

1. 本地订阅进入 PAST_DUE，不再授予新的 Pro 商业额度。
2. 已在线项目继续运行至原 `currentPeriodEnd + 3 天`。
3. 宽限期内付款恢复后，项目直接延长至新周期结束后 3 天，不创建恢复部署。
4. 宽限期结束仍未恢复付款，项目进入 EXPIRED 并展示过期页。

#### Free 项目已经过期后订阅

1. 订阅激活成功是自动恢复的前置条件。
2. latest retained artifact 存在时，创建 `SUBSCRIPTION_RESTORE` 异步部署。
3. 自动恢复不消耗日部署次数、月部署次数或上传流量。
4. 恢复成功后继续使用原项目固定链接，过期页被原子替换。
5. retained artifact 已删除时不伪造成功，项目保持过期并提示重新上传。

#### 订阅失效后再次订阅

1. 在新套餐项目上限内，优先按 latest 成功部署创建时间倒序选择项目；没有成功部署时使用项目更新时间倒序。
2. READY 且仍在线的项目只更新租约。
3. EXPIRED 且 retained artifact 存在的项目自动恢复。
4. retained artifact 不存在的项目标记为需要重新上传。
5. 超过项目上限的项目进入套餐归档，不删除项目、部署记录或仍在保留期内的 retained artifact。
6. 同一时间相同时使用项目 ID 倒序作为稳定次序。

### 项目上限与归档

套餐归档必须与 Abuse BLOCKED 分开，不能复用安全封禁语义。

项目增加独立托管状态：

```text
HOSTED
ARCHIVED
```

- `HOSTED`：可以按当前账号权益在线或进入恢复。
- `ARCHIVED`：不公开托管，不允许自动恢复，不参与当前套餐已托管项目数。
- Abuse 状态继续使用现有项目 `status`，并且 BLOCKED 优先于托管状态。
- 项目进入 ARCHIVED 时清除在线 `current`，但保留项目和部署记录；固定链接展示不泄露原因的通用不可用页。
- 用户删除一个 HOSTED 项目后，系统不擅自恢复任意 ARCHIVED 项目；控制台提示用户选择需要恢复的项目，避免公开意外内容。
- 用户升级到更高项目上限时，可以一次确认后批量恢复最近项目。

### 访问方式

- 宽限期内保留项目当前 PUBLIC 或 PASSWORD 访问方式。
- 失去 Pro 权益后不能新设或修改 PASSWORD，但已有密码项目在宽限期内仍可按原密码访问。
- PUBLIC 和 PASSWORD 项目自动恢复时复用现有访问方式和密码哈希。
- PRIVATE 项目保持私密并等待所有者明确选择，不因订阅激活自动恢复或公开。
- BLOCKED、ARCHIVED 的项目不能因为订阅激活自动公开。

## 后端设计

### 账号权益快照

扩展现有 `AccountEntitlementSnapshot`，一次订阅读取同时提供：

- `plan`
- `entitlements`
- `policy`
- `subscriptionStatus`
- `currentPeriodEnd`
- `cancelAtPeriodEnd`
- 是否属于有效 Pro 托管

HTTP 请求、Worker 和清理任务在一次入口处理中只解析一次快照，避免套餐、周期和限额来自不同订阅读取时点。

### 托管生命周期

深化现有 `ActivePreviewService`，集中负责：

1. 计算新部署托管截止时间。
2. 更新 latest 的 `previewExpiresAt`。
3. 同步更新 latest retained artifact 的保留截止时间，避免网站仍在线但自动恢复产物提前清理。
4. 清理候选在删除前续租有效 Pro。
5. 执行真正的过期、托管渠道删除和过期页发布。

`AccountPolicy.previewExpires` 对普通 CUSTOMER 继续为 `true`，含义调整为“失去托管权益后会过期”。不能简单把 Pro 改为 `false`，否则取消订阅后 `previewExpiresAt=null` 的记录无法进入清理查询。

### 订阅事件接入

每次本地订阅保存 ACTIVE 状态后：

1. 立即刷新当前可托管项目的租约。
2. 只有从非有效 Pro 转为有效 Pro 时才启动自动恢复。
3. 普通续费只刷新租约，不创建恢复部署。
4. Stripe Webhook 重试和小时级对账可以重复调用，结果必须幂等。

清理任务仍是最终安全兜底：

```text
扫描到即将过期或已经过期
  → 解析账号权益快照
  → 有效 Pro：更新租约并跳过邮件与删除
  → 非有效 Pro：按托管截止时间提醒或过期
  → 权益解析异常：跳过破坏性删除，记录日志并下次重试
```

### 自动恢复

新增订阅恢复模块，职责限定为：

1. 按新套餐上限选择项目。
2. 区分直接续租、可自动恢复、需要重新上传和套餐归档。
3. 使用现有 retained artifact 创建异步恢复部署。
4. 汇总恢复结果供控制台和邮件使用。

自动恢复幂等规则：

- 来源部署必须是当前项目 latest。
- 只有 EXPIRED 且 retained artifact 存在的部署可作为来源。
- 若已经存在同项目、同来源、`deploymentSource=SUBSCRIPTION_RESTORE` 且状态为 QUEUED、BUILDING 或 READY 的部署，不重复创建。
- FAILED 允许后台有限重试；超过重试次数后等待用户重试或重新上传。
- 自动恢复部署不扣商业额度，但仍受上传安全上限、并发安全上限和 Abuse 校验。
- 如果旧套餐产物超过新套餐单文件上限，项目进入 RESTORE_UNAVAILABLE，提示升级套餐或重新上传符合当前上限的产物。

恢复完成前固定链接继续展示完整过期页。只有新部署成功并完成 latest 激活后才切换 `current`。

### 数据迁移

迁移包含：

1. 增加独立项目托管状态，历史项目默认 `HOSTED`。
2. 为当前有效 Pro 的 READY latest 部署回填 `currentPeriodEnd + 3 天`。
3. 同步延长对应 latest retained artifact 的截止时间。
4. 上线前统计“有效 Pro 但 latest 已为 EXPIRED”的项目；有 retained artifact 的进入一次性自动恢复，无产物的进入需要重新上传状态。
5. 不自动恢复 BLOCKED、已删除或 PRIVATE 项目。

## 前端与接口设计

### 项目托管状态

项目相关接口在保留现有 `previewExpiresAt` 兼容字段的同时，新增稳定状态：

```text
FREE_ACTIVE
SUBSCRIPTION_ACTIVE
GRACE
RESTORING
EXPIRED
ARCHIVED
RESTORE_UNAVAILABLE
BLOCKED
```

同时返回：

- `hostingUntil`
- `paidThrough`
- `autoRenews`
- `restorable`
- `hostingStatus`

前端不再仅根据本地时间推断完整托管状态，避免 PAST_DUE、取消续订、自动恢复和归档在多个页面出现不同结果。

### 时间标签

- Free：`预览到期时间`
- Pro ACTIVE：`当前托管保障至`
- `cancelAtPeriodEnd=true`：`最终托管截止时间`
- PAST_DUE：`宽限期截止时间`
- EXPIRED：`托管已暂停`

> **持续托管中**  
> 当前已保障至 2027 年 7 月 30 日  
> 已一次保障 12 个月

提前取消：

> **已取消自动续订**  
> Pro 权益于 2026 年 8 月 30 日结束  
> 网站将保留至 2026 年 9 月 2 日，包含 3 天宽限期

扣费失败：

> **付款待处理，网站仍在运行**  
> 请在 2 天 14 小时内更新付款方式，避免网站暂停

> **托管已暂停**  
> 重新订阅后，系统将使用保留产物自动恢复，无需重新上传

## 邮件通知设计

正常后台续租不重复发送 PreviewShip 产品邮件；Stripe 收据承担正常扣款通知。只对需要用户知道或处理的状态发信。

| 事件 | 邮件行为 |
|---|---|
| Free 部署成功 | 告知固定链接和 3 天到期时间 |
| Free 到期前 24 小时 | 到期提醒和升级入口 |
| 订阅成功 | 告知持续托管生效、保障日期和待恢复项目数 |
| 正常自动续费 | 不发额外产品邮件，保留 Stripe 收据 |
| 取消自动续订 | 告知权益结束时间和最终托管截止时间 |
| 扣费失败 | 立即告知付款处理入口和托管截止时间 |
| 宽限期剩余 24 小时 | 再提醒一次网站暂停时间 |
| 宽限期结束 | 告知托管已暂停和恢复方式 |
| 自动恢复完成 | 汇总已恢复项目 |
| 自动恢复最终失败 | 告知失败项目及重试或重新上传入口 |
| 项目超过新套餐上限 | 汇总恢复数量和归档数量 |

邮件使用“订阅 ID + currentPeriodEnd + 事件类型”作为通知 episode key，避免 Webhook 重投和对账重复发信。多项目恢复使用汇总邮件，不按项目连续轰炸用户。

## 公开过期页

项目过期后，固定链接继续展示过期页，直到项目恢复、主动删除或安全封禁。

公开访问者只看到：

> **此预览暂时不可用**  
> 项目所有者可以登录 PreviewShip 查看原因并恢复此链接。

按钮：

> 项目所有者登录

公开页不显示套餐、扣款失败、取消续订、artifact 是否存在或项目上限等所有者信息。按钮携带项目和来源部署恢复上下文，登录后由控制台展示真实操作：

- Free：升级 Pro 并自动恢复，或重新部署获得新的 3 天；
- PAST_DUE：更新付款方式；
- CANCELED：重新订阅并自动恢复；
- RESTORING：展示恢复进度；
- RESTORE_UNAVAILABLE：重新上传；
- ARCHIVED：升级套餐或释放项目槽位；
- BLOCKED：仅展示安全封禁信息，不提供商业恢复入口。

## 异常与回退

1. Stripe Webhook 延迟或漏投：小时级对账补齐；清理前权益重查保护有效 Pro。
2. 权益解析或数据库查询失败：清理任务不得删除网站，记录错误后重试。
3. `currentPeriodEnd` 缺失：使用 48 小时滚动安全租约并持续对账。
4. 自动恢复队列投递失败：保留过期页和 retained artifact，后台重试。
5. 自动恢复构建失败：不替换 latest，原过期页继续存在。
6. retained artifact 删除失败：记录技术告警，但不能误报为可恢复。
7. 邮件发送失败：不影响订阅、续租或恢复事务，释放通知去重标记后重试。
8. Webhook 重复：续租更新幂等；自动恢复不产生重复部署。
9. 套餐配置缺失：明确失败并跳过破坏性清理，不能静默按 Free 删除。
10. Abuse BLOCKED、用户封禁和项目删除始终优先于订阅权益。

## 可观测性

记录以下技术与业务结果：

- 续租项目数量、跳过数量和失败数量；
- 进入宽限期、过期和恢复的项目数量；
- 自动恢复 QUEUED、READY、FAILED；
- 需要重新上传和套餐归档数量；
- 清理前因有效订阅而保护的候选数量；
- Stripe 状态与本地托管租约不一致告警；
- 邮件 episode 的发送、跳过和失败。

自动续租本身不记录新的部署成功业务事实，不增加部署次数，也不伪造成用户再次发布。

## 测试

### 后端单元测试

- Free 部署仍为 3 天。
- 月付和年付都使用 `currentPeriodEnd + 3 天`。
- ACTIVE 且周期缺失使用滚动安全租约。
- cancelAtPeriodEnd 不提前停止托管。
- PAST_DUE 在宽限期内仍在线，宽限结束后过期。
- 有效 Pro 清理候选被续租且不调用 provider 删除。
- 权益解析异常时不执行破坏性清理。
- latest artifact 截止时间随托管租约延长。
- 自动恢复不扣部署或上传额度。
- 重复 Webhook 不创建重复恢复部署。
- artifact 不存在时返回需要重新上传。
- BLOCKED、PRIVATE 和 ARCHIVED 不被错误公开。
- 多项目恢复遵守项目上限和稳定排序。

### 后端集成测试

- Stripe 激活、续费、PAST_DUE、CANCELED 与小时级对账完整时间线。
- 自托管 `current`、过期页和自动恢复原子切换。
- Vercel 与自托管两种 provider 生命周期一致。
- 数据迁移正确回填当前有效 Pro，不恢复封禁项目。
- 清理任务、对账任务和 Webhook 并发时不重复恢复、不误删。

### 前端测试

- Free、月付、年付、取消中、PAST_DUE、RESTORING、EXPIRED、ARCHIVED 文案。
- 月付显示按月保障，年付显示一次保障十二个月。
- 有效 Pro 不显示 Free 到期升级提示。
- 公开过期页不泄露账单信息。
- 自动恢复中禁用重复恢复操作。
- retained artifact 不存在时只提供重新上传。
- 超额项目展示升级或释放槽位入口。

### 邮件测试

- 每个通知 episode 只发送一次。
- 正常续费不重复发送产品邮件。
- 取消、扣费失败、24 小时提醒和过期时间一致。
- 多项目恢复发送一封汇总邮件。
- INTERNAL 不收到商业托管邮件。

## 发布顺序

1. 发布数据库迁移和后端兼容读写。
2. 发布托管租约刷新、清理保护和自动恢复。
3. 验证有效 Pro 项目回填与异常项目审计。
4. 发布控制台状态、套餐卡和多语言文案。
5. 更新公开过期页。
6. 更新 CLI、MCP、Extension、README 和官网文档中的 30/365 天表述。
7. 观察一个月付续费周期，确认无误删、重复恢复和重复邮件。

回滚时必须保留清理前有效订阅保护，不能回滚为会删除已改成订阅租约的项目；前端文案可以独立回滚。

## 验收标准

1. 有效 Pro 项目跨越原 30/365 天部署时间后仍可访问。
2. 正常续费不产生新部署且自动延长全部符合额度的项目。
3. 取消或扣费失败后，项目准确运行至当前周期结束后 3 天。
4. 宽限期内恢复付款无网站中断。
5. 已过期且 artifact 存在的项目重新订阅后自动恢复同一固定链接。
6. artifact 已删除时明确提示重新上传。
7. 超过新套餐项目上限的项目归档而不删除。
8. 月付和年付均表达持续托管，同时年付明确展示一次保障十二个月及更高额度。
9. 公开过期页保持可访问且不泄露账单信息。
10. 关键邮件完整、去重且时间与控制台一致。
